## 1. 背景と問題提起

`minmax-fx-day-trading-lab`（親 PJ）は 2026-08-13 起票から 16 日間で 213 コミット・19-28 試行・11 戦略を試行し、**SYS-FX007/008/009/010/013/014/015/017/019/020/021 が全て不採用**、SYS-FX011 は外部レビューで 5 件の致命的欠陥発覚、SYS-FX012 はフォワードテスト中ですでに「必須 KPI 13/18・C 査読未実施」のまま進行中。

この**全滅パターン**を構造解析した結果、**評価フレームワーク自体に以下の構造的欠陥**が判明（2026-08-29 時点）:

| # | 問題 | 影響 | 元の閾値 |
|---|---|---|---|
| **#1** | K4m (ペイオフレシオ) が市場構造的に達成不能 | SYS-FX011 で最高 1.18、T-13 トレール専業化でも 1.18 まで | ≥ 1.5 |
| **#2** | min_n_trades=300 が「週1厳選」戦略と物理的矛盾 | Train 74週 × 5通貨 = 上限 370件、実効 n (相関考慮後) は 1,027 件必要 | 300 |
| **#3** | permutation_test_clustered が 4 通貨構成で p 値下限 0.3158 に張り付く | 全勝ケースでも有意水準達成不能 | < 0.05 |
| **#4** | K3m (最大連続損失 ≤ 5) が i.i.d. 帰無分布下でも 60〜72% で PASS | 観測値 0.28〜0.72 パーセンタイル = ランダムと区別不能 | ≤ 5 |
| **#5** | 選択バイアスの補正なし（19-28 試行・213 コミット蓄積） | Bailey & Lopez de Prado 2014 の DSR で直接捕捉されるべき問題 | — |

これらは独立ではなく、**選択バイアスを媒介に接続している**。個別の閾値修正では不十分で、**DSR (Deflated Sharpe Ratio) を必須 KPI 化し、他の閾値は DSR と整合する形に揃える**のが論理的に一貫した解。

## 2. v0.2 推奨フレームワーク（4 つの判断）

### 2.1 K4m (ペイオフレシオ) **1.5 → 1.2**

**妥当性根拠**:
- 業界基準（Lopez de Prado "Advances in Financial ML" 第 12 章、Bailey et al. 2014/2017）: 機関的クオンツ基準で 0.8〜1.2 が標準
- 1.0 は「勝ち負け同値」を許容し指標の識別力を失う、1.5 は市場構造上ほぼ到達不能
- 1.2 は「利益が損失より 20% 上」を要求し、わずかな識別力を保持
- 経験的裏付け: SYS-FX011 トレール専業化で最高 1.18、SYS-FX018 breakeven=2.0 で 1.549（ただし n=219 < 300 で F）

### 2.2 min_n_trades **300 維持 + DSR 連動**（安全弁として n ≥ 50 hard fail）

**妥当性根拠**:
- 物理的矛盾の解消: DSR 補正後の Sharpe 期待値が n 不足を織り込むため、別個に min_n_trades を固定する必要がない
- 業界標準との整合: Bailey 2014 DSR は試行数 N + サンプル長 T + Sharpe 分散を同時補正し、MinTRL を返す
- 300 撤廃はサンプル 0 でも「有意」と判定されるリスクが残るため、n ≥ 50 を hard fail として安全弁だけ残す
- 戦略コンセプト別閾値（週1厳選=100, HFT=1000）は戦略ごと事前登録が必要で再現性が崩れる

### 2.3 permutation 検定の **block 版デフォルト化**

**妥当性根拠**:
- 外部レビュー T-06 (2026-08-21) で `permutation_test_block()` 実装済 — コードはあるが clustered 版と並存
- 3 関数を並存させると新規利用が分散、block 版が標準になれば新規 clustered 利用は `@deprecated` 警告で停止
- 1 関数化（method 引数）は既存呼び出し 100+ 箇所の修正が必要、ROI 低い

### 2.4 DSR (Deflated Sharpe Ratio) **≥ 0.95 を必須 KPI 化**

**妥当性根拠**:
- 選択バイアスの直接補正: 本 PJ は 213 コミット・19-28 試行。Bailey 2014 の E[max SR*] 公式で、N=19〜28 と Var(SR) を入れると帰無仮説下の Sharpe 上限は約 0.4〜0.7
- 机上シミュレーション: SYS-FX011 T-13 (perm_p=0.035, SR=2.94, 7 試行) → DSR ≈ 0.85-0.92（DSR ≥ 0.95 未達だが有意水準に近い）
- 参考値扱い（D2）では「レポートに載せるが判定は変えない」になり、何も防げない
- DSR + permutation 両方必須（D3）は厳しすぎ、DSR 単独で十分

## 7. オープン問題

- **C 査読の独立性**: Mavis 環境では物理的に単一 LLM のため、`compute_dsr()` 実装と C 査読を別インスタンスで実行しても独立性は擬似的にしか確保できない。**この制約を明示的に開示**し、最終 GO は司令塔判断に委ねる
- **DSR の N (試行数) の数え方**: 19-28 試行は「保存された spec 改訂の数」と「実際に試したパラメータ組み合わせ」の両方をどう合算するかで解釈が変わる。Bailey 2014 は conservative に「より大きい N」を推奨
- **動的閾値 vs 固定閾値**: DSR は試行数依存だが、K4m=1.2 のような固定閾値は試行数に依存しない。長期的に「戦略コンセプト × 試行数 → 動的閾値テーブル」化も検討余地
